BazarPro ist Open Source (MIT). Mit Docker Compose läuft es auf einem einzelnen Server – mit eigener Datenbank, HTTPS über Let's Encrypt und ohne dass du etwas selbst bauen musst. Plane für die Einrichtung etwa eine halbe Stunde ein.

Die Anleitung beschreibt BazarPro **ab Version 2.0**. Ab dieser Version hat BazarPro ein eigenes Backend mit einer PostgreSQL-Datenbank. Läuft bei dir noch eine ältere Version mit Convex, folge der Anleitung [Umstieg von Convex](/selbst-hosten/umstieg-von-convex/).

**Du brauchst:**

- einen Linux-Server mit [Docker](https://docs.docker.com/engine/install/) und Docker Compose, mindestens 2 GB RAM, die Ports **80** und **443** müssen erreichbar sein
- eine Domain, bei der du DNS-Einträge anlegen kannst
- ein E-Mail-Postfach mit SMTP-Zugang – BazarPro verschickt darüber die Bestätigungscodes bei Registrierung und Passwort-Reset

## Ein Verein oder eine Plattform?

BazarPro kennt zwei Betriebsarten. Du wählst sie mit **`BAZARPRO_MODE`** in der `.env`:

| | `single` (Standard) | `platform` |
| --- | --- | --- |
| **Für wen** | ein Verein, eine Kita, eine Schule mit eigenen Basaren | viele Veranstalter auf einer Seite, wie bazarpro.de |
| **Startseite** | Name, Logo und Basare des Vereins | Werbeseite von BazarPro mit allen öffentlichen Basaren |
| **Basare anlegen** | nur Administratoren | jeder Nutzer |
| **Freigabe öffentlicher Basare** | entfällt | durch Administratoren |
| **Rolle „Veranstalter“** | nur für Administratoren und das Team eines Basars | für alle |
| **Name in Kopfzeile und E-Mails** | Name des Vereins | BazarPro |

Für die allermeisten Installationen ist `single` richtig. Die Daten sind in beiden Betriebsarten gleich, du kannst später wechseln.

## Was läuft auf dem Server?

| Dienst | Aufgabe |
| --- | --- |
| **traefik** | Nimmt alle Anfragen entgegen und holt die HTTPS-Zertifikate bei Let's Encrypt. |
| **app** | Die BazarPro-Webseite. |
| **backend** | Die Server-Logik unter `/api`: Anmeldung, Live-Updates, Uploads, E-Mails und regelmäßige Aufgaben wie Erinnerungsmails. Hochgeladene Fotos und Logos liegen im Docker-Volume `bazarpro_files`. |
| **postgres** | Die Datenbank ([PostgreSQL](https://www.postgresql.org/)) im Docker-Volume `bazarpro_postgres_data`. |

## Installation

<Steps>

1. **DNS-Eintrag anlegen.** Deine Domain muss auf die IP-Adresse deines Servers zeigen, z. B. `basar.example.org` mit einem A-Eintrag (und bei IPv6 einem AAAA-Eintrag). Weitere Namen braucht BazarPro nicht.

2. **Dateien herunterladen.** Auf dem Server in einem neuen Ordner:

   ```bash
   mkdir bazarpro && cd bazarpro
   curl -O https://raw.githubusercontent.com/BazarPro/core/main/docker-compose.selfhost.yml
   curl -o .env https://raw.githubusercontent.com/BazarPro/core/main/.env.selfhost.example
   ```

3. **Einstellungen eintragen.** Öffne die Datei `.env` und trage mindestens ein:

   - **`DOMAIN`** – deine Domain ohne `https://`, z. B. `basar.example.org`
   - **`POSTGRES_PASSWORD`** – ein zufälliges Passwort für die Datenbank, z. B. erzeugt mit `openssl rand -hex 24`. Lege es einmal fest und ändere es danach nicht mehr: Die Datenbank übernimmt es beim ersten Start.
   - **`ACME_EMAIL`** – deine E-Mail-Adresse, Let's Encrypt warnt dich dort vor ablaufenden Zertifikaten
   - **`BAZARPRO_VERSION`** – die Version, die du installieren möchtest, mindestens `v2.0.0`. Alle Versionen findest du unter [Releases](https://github.com/BazarPro/core/releases).
   - **`BAZARPRO_MODE`** – `single` für einen Verein (Standard) oder `platform`, siehe oben
   - **`ADMIN_EMAIL`** – die E-Mail-Adresse, mit der du dich gleich registrierst. Dieses Konto wird automatisch Administrator.
   - **`AUTH_SMTP_…`** und **`AUTH_EMAIL_FROM`** – die Zugangsdaten deines E-Mail-Postfachs. Die Adresse in `AUTH_EMAIL_FROM` muss zu diesem Postfach passen, sonst landen die Mails im Spam. Als Absendername verwendet BazarPro im Modus `single` den Namen deines Vereins aus den Einstellungen.

4. **BazarPro starten.**

   ```bash
   docker compose -f docker-compose.selfhost.yml up -d
   ```

   Beim ersten Start dauert es ein bis zwei Minuten, bis alle Images geladen sind. Das Backend legt dabei die Tabellen der Datenbank an. Den Fortschritt siehst du mit:

   ```bash
   docker compose -f docker-compose.selfhost.yml logs -f backend
   ```

   Sobald dort **`listening`** steht, ist BazarPro bereit.

5. **Konto anlegen.** Öffne deine Domain im Browser, klicke auf **Registrieren** – mit der Adresse aus `ADMIN_EMAIL` – und bestätige sie mit dem Code aus der Bestätigungsmail. Sobald die Adresse bestätigt ist, ist dein Konto Administrator. Nach einem Neuladen der Seite findest du im Rollenwechsel der Seitenleiste den Bereich **Admin**.

   Erst nach der Bestätigung wird das Konto Administrator. So kann niemand die Adresse vorher für sich registrieren.

6. **Weitere Administratoren** ernennst du mit:

   ```bash
   docker compose -f docker-compose.selfhost.yml exec backend bazarpro-backend admin vorstand@example.org
   ```

   Das Konto muss dafür schon registriert sein.

</Steps>

<Aside type="caution" title="Seite lädt nicht oder zeigt einen Zertifikatsfehler?">
  - Prüfe, ob deine Domain auf den Server zeigt, z. B. mit `dig +short basar.example.org`.
  - Let's Encrypt prüft die Domain über Port 80. Eine Firewall darf ihn nicht blockieren.
  - Fehlermeldungen beim Holen der Zertifikate zeigt `docker compose -f docker-compose.selfhost.yml logs traefik`.
  - Startet das Backend nicht, steht der Grund in `docker compose -f docker-compose.selfhost.yml logs backend`.
</Aside>

## Nach der Installation: deinen Verein einrichten

Bevor du den ersten Basar anlegst, richte als Administrator zwei Dinge ein:

<Steps>

1. **Einstellungen** (Admin › Einstellungen):

   - **Name** und **Logo** deines Vereins erscheinen in der Kopfzeile, auf der Startseite und in allen E-Mails.
   - Die **Kontakt-E-Mail** steht im Footer und auf der Kontaktseite.
   - Unter **Startseite** wählst du, ob die Startseite eine Übersicht aller Basare zeigt oder direkt zum laufenden bzw. nächsten Basar führt.
   - **Webanalyse mit Plausible** ist optional, siehe unten.

2. **Rechtstexte** (Admin › Rechtstexte): **Impressum, Datenschutzerklärung und AGB** sind Pflicht, und verantwortlich bist du als Betreiber. Solange du keinen Text gespeichert hast, zeigt BazarPro auf diesen Seiten den Hinweis „Diese Seite wurde noch nicht eingerichtet“.

   Mit **Vorlage laden** bekommst du einen Entwurf, in dem du alle Platzhalter in doppelten eckigen Klammern ersetzt, z. B. `[[Name des Vereins]]`. Die Übersicht im Admin-Bereich warnt, solange Platzhalter übrig sind. Jede Änderung wird als Version gespeichert.

</Steps>

<Aside type="caution" title="Vorlagen sind keine Rechtsberatung">
  Die Vorlagen für Datenschutzerklärung und AGB stammen von der Plattform bazarpro.de. Sie müssen an deinen Verein angepasst werden – die AGB zum Beispiel, weil ihr als Verein selbst Veranstalter seid. Lass die Texte vor der Veröffentlichung rechtlich prüfen.
</Aside>

Danach legst du unter der Rolle **Veranstalter** deinen ersten Basar an, siehe [Einen Basar anlegen](/veranstalter/basar-anlegen/). Im Modus `single` ist ein öffentlicher Basar sofort sichtbar, eine Freigabe ist nicht nötig.

## Webanalyse mit Plausible (optional)

BazarPro kann die Besucherzahlen mit [Plausible Analytics](https://plausible.io) erfassen – ohne Cookies. Plausible ist nicht in BazarPro enthalten: Du brauchst eine eigene Plausible-Installation ([Community Edition](https://github.com/plausible/community-edition)) oder ein Konto bei plausible.io.

Eingeschaltet wird die Webanalyse unter **Admin › Einstellungen › Webanalyse mit Plausible**: Domain und Plausible-Server eintragen, aktivieren, speichern. Ein Neustart ist nicht nötig. Alternativ kannst du `PLAUSIBLE_DOMAIN` und `PLAUSIBLE_API_HOST` in der `.env` setzen. Die Einstellungen im Admin-Bereich haben Vorrang.

Steht in deiner Datenschutzerklärung die Zeile `{{webanalyse}}` (in der Vorlage ist sie enthalten), fügt BazarPro dort automatisch einen Abschnitt zu Plausible ein, solange die Webanalyse aktiv ist. Nutzt du plausible.io, brauchst du zusätzlich einen Vertrag zur Auftragsverarbeitung mit dem Anbieter.

## Erst einmal ausprobieren?

Wenn du BazarPro nur testen möchtest, kannst du Beispieldaten laden: mehrere Basare, Artikel und Konten, unter anderem `admin@bazarpro.de`, `user1@bazarpro.de` (Veranstalter) und `seller@bazarpro.de` (Verkäufer), alle mit dem Passwort `123456`.

```bash
docker compose -f docker-compose.selfhost.yml exec backend bazarpro-backend seed
```

<Aside type="danger">
  Lade die Beispieldaten nie auf einer Instanz, die du wirklich nutzt: Die Konten haben ein öffentlich bekanntes Passwort.
</Aside>

## Anmeldung mit GitHub oder Google

Optional können sich Nutzer mit ihrem GitHub- oder Google-Konto anmelden. Lege dafür beim Anbieter eine OAuth-App an und trage als Callback-URL ein:

- GitHub: `https://<DOMAIN>/api/auth/oauth/github/callback`
- Google: `https://<DOMAIN>/api/auth/oauth/google/callback`

Client-ID und Secret kommen in die `.env` (`AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET` bzw. `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET`). Danach BazarPro neu starten, siehe unten.

Erwähne die Anmeldung über GitHub oder Google auch in deiner Datenschutzerklärung.

## Einstellungen ändern und aktualisieren

Nach jeder Änderung an der `.env` und für ein Update auf eine neue Version – vorher `BAZARPRO_VERSION` anpassen:

```bash
docker compose -f docker-compose.selfhost.yml pull
docker compose -f docker-compose.selfhost.yml up -d
```

Das Backend bringt die Datenbank beim Start selbst auf den Stand der neuen Version. Deine Daten bleiben erhalten. Mach vor einem Update trotzdem eine Datensicherung.

## Datensicherung

Eine Sicherung besteht aus zwei Dateien: dem Abzug der Datenbank (Konten, Basare, Artikel, Verkäufe) und einem Archiv der hochgeladenen Fotos und Logos. Im Ordner mit der `docker-compose.selfhost.yml`:

```bash
docker compose -f docker-compose.selfhost.yml exec -T postgres \
  pg_dump -U bazarpro --format=custom bazarpro > bazarpro-$(date +%F).dump
docker compose -f docker-compose.selfhost.yml exec -T backend \
  tar -czf - -C /data/files . > files-$(date +%F).tar.gz
```

Bewahre die Sicherung an einem anderen Ort als dem Server auf. Am besten richtest du dafür einen täglichen Cronjob ein.

**Wiederherstellen:** Die folgenden Befehle ersetzen **alle** aktuellen Daten durch den Stand der Sicherung. Das Backend wird dafür kurz angehalten:

```bash
docker compose -f docker-compose.selfhost.yml stop backend
docker compose -f docker-compose.selfhost.yml exec -T postgres \
  pg_restore -U bazarpro --clean --if-exists --no-owner -d bazarpro < bazarpro-2026-10-21.dump
docker compose -f docker-compose.selfhost.yml run --rm -T --no-deps --entrypoint sh backend \
  -c 'find /data/files -mindepth 1 -delete && tar -xzf - -C /data/files' < files-2026-10-21.tar.gz
docker compose -f docker-compose.selfhost.yml start backend
```

## Direkt in die Datenbank schauen

Für einen Blick in die Daten öffnest du eine SQL-Konsole:

```bash
docker compose -f docker-compose.selfhost.yml exec postgres psql -U bazarpro
```

<Aside type="caution">
  In der Konsole kannst du alle Daten lesen und ändern. Änderungen an den Tabellen gehen an den Prüfungen von BazarPro vorbei – mach vorher eine Datensicherung.
</Aside>
